# 待確認位置

座標可疑、但自動比對無法定案的場站。確認後把座標寫進 `data/coord-overrides.json`
（key＝`縣市|場站名`，最高優先、無條件覆蓋，不會被下次爬蟲蓋掉），並從本檔移除。

## 判定方式

三個獨立來源互比，落差大＝可疑：

| 來源 | 定位對象 | 典型失效 |
| --- | --- | --- |
| Nominatim / OSM | 地址門牌（`geocode-carmochi.mjs`，結果存 `data/geocode-cache.json`） | 門牌不存在就退成整條路的中心；「對面／旁」失真；路名撞名跨區 |
| NLSC 國土測繪中心 | 政府門牌坐標（`geocode-fallback.mjs`） | 門牌本身對，但停車場不在門牌上 |
| Autopass POI | **停車場實體**（`api.autopass.xyz/v3/pois`，`scrape-autopass.mjs`） | 冷門場站未收錄；同名多筆 |

Autopass 定位的是停車場本身而非地址，可信度最高，優先採用。

背景：2026-08-17 對全部 595 筆「座標由地址反查」的場站跑過 NLSC 交叉比對，依落差分成
A 類（>1km，59 筆）、B 類（500m–1km，78 筆）、C 類（200–500m，129 筆），
另加 D 類（地址無門牌號、結構上無法反查，57 筆）。全部比對 Autopass POI 後，
**287 筆已用 Autopass 座標修正**（寫入 `coord-overrides.json`），剩下這 13 筆待人工確認。

其中 11 筆原本是「同名候選多筆」，因候選座標相近（緯經度小數第 2 位相同）、
差異只是同場站的不同出入口或大小車分區，已依「取地址最接近者」規則自動定案。
